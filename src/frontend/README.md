# Dict frontend

The frontend reads `WIKBLB05` datasets and exposes the same presentation model through the CLI, TUI, HTML/JSON exports, and local HTTP server.

## Native Lua expansion

Lua expansion has one implementation: the dump-specific `dict-native-expansion-worker` generated by the coordinated build.

A runtime root contains the provider/source assets and the dump-specific native worker. The generic `dict` executable launches that worker through a bounded framed protocol. Missing or incompatible runtime assets are explicit failures.

Use a linked dataset directly:

```sh
dict lookup cat --root ROOT
dict search ca --root ROOT --format html
dict tui --root ROOT
dict serve --root ROOT --port 8787
```

Override the runtime root when needed:

```sh
dict lookup cat --root ROOT --runtime RUNTIME_ROOT
```

`--runtime-timeout-ms N` bounds one expansion request. Worker crashes and timeouts affect only that worker process; the next request creates a replacement.

The framed request contains the runtime root, entry title, exact source, optional dictionary root, and language. Responses use `dict.expansion.v1` with backend `lua-aot`.

## Result model

JSON uses `dict.results.v1`. Entry expansion metadata is:

```json
{
  "backend": "lua-aot",
  "status": "ok",
  "diagnostic": null
}
```

A failed expansion is represented explicitly and the exact source remains available when requested. Human-readable rendering never disguises a failed expansion as successful Lua output.

## Local server

```sh
dict serve --root ROOT --port 8787
```

The server binds to `127.0.0.1`. `--port 0` selects an available port. Search/index access and Lua expansion use separate synchronization so a slow expansion does not hold the dictionary search lock.

The server retains one native Lua worker across requests. `/api/stats` reports `lua_worker_starts` and `lua_requests`.

## HTML reader

The SolidJS frontend is under `src/frontend/web/`.

```sh
cd src/frontend/web
bun install
bun run build
```

The build writes the self-contained asset used by native HTML exports. The browser receives semantic `dict.results.v1` data and does not execute Lua itself.

## Source and companions

Core language blobs may defer large sections into companion blobs. Full JSON/HTML/source operations resolve required companions. `--core-only` intentionally exports only the core and labels omitted bodies instead of pretending they are empty.

`--with-source` includes exact source alongside the semantic presentation model. `--format source` emits only source bytes.

## Media

Media acquisition is explicit and separate from dictionary reads:

```sh
zig build fetch-media -- RESULTS.json ROOT/media
```

HTML exports can embed verified local media. Normal dictionary rendering does not require network access.

## Validation

Relevant gates:

```sh
zig build test
zig build test-runtime
zig build test-reader
zig build test-http
```

Runtime changes must be validated through the real generated native worker, not a mocked expansion response.
